- Date: 2026-03-10
- Goal: 定位“新机自动跳 Dashboard / 清理后无法回安装页 / 入口仍出现命令行提问”三类问题的根因，并形成可执行改造方案（先调研不改功能）
- Selected feature id: 003-opensparrow-ui-reset-hardening（规划阶段）
- Investigation scope:
  - 入口链路：mac 顶层入口与 legacy `usb-pack/mac/run-openclaw-usb.command`、Windows 顶层入口 `win/01-开始部署.cmd`
  - 状态接口：`usb-pack/ui/server.mjs` `/api/status`
  - 清理接口：`usb-pack/ui/server.mjs` `/api/cleanup`
  - 前端跳转：`usb-pack/ui/public/index.html` `init()`
- Repro commands (highlights):
  - 构造“仅有 openclaw.json”profile 后请求 `/api/status`，实际返回 `installed:true`
  - 调用 `/api/cleanup` 后再次请求 `/api/status`，仍返回 `installed:true`
  - `openclaw daemon status --json` 实测无顶层 `status` 字段，仅有 `service.runtime.status`
  - `openclaw uninstall --service --state --workspace --yes --non-interactive` 实测可完成全量重置
- Confirmed root causes:
  1) daemon 状态解析使用 `parsed.status ?? 'running'`，导致假阳性；
  2) cleanup 只清服务/端口，不清 profile 状态目录；
  3) 仍保留可触发 CLI 交互的旧入口（mac legacy 可直调、Windows 顶层当前仍默认 CLI）；
  4) 所谓“硬编码”主要来自 profile 残留配置被 Dashboard 读取。
- Analysis deliverables:
  - 新 spec/plan/tasks：`specs/003-opensparrow-ui-reset-hardening/`
  - 调研报告：`longrun/workspaces/openclaw-usb-portable/execution/docs/opensparrow-ui-install-reset-investigation-20260310.md`
- Open questions:
  - “全量重置”是否默认包含 skills 目录（`~/.claude/.codex`）删除，还是做可选项
  - Dashboard 保留“轻量清理”与“全量重置”双按钮，还是只保留全量重置
